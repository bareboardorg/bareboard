    ESP32 Family

    Espressif’s Wi-Fi + Bluetooth microcontroller that ate the IoT world. Cheap, capable, and — unusually for the industry — genuinely well documented.

    FCC ID

    FCC ID: 2AC7Z-ESPWROOM32 (Grantee: 2AC7Z = Espressif Systems) for the ESP32-WROOM-32 module.

    • Other variants: 2AC7Z-ESPWROOM32UE, 2A9ZM-WROOM32E (32E variant)
    • Available: Test reports, antenna specs, user manuals, RF exposure docs

    What the FCC filing revealed

    The FCC filing for this device includes the documents manufacturers are required to submit: external photos, internal photos, test setup photos, RF test reports, and the user manual. These are public record at fccid.io.

    What you can typically find:

    • Internal photos — board layout, chip placement, shielding, antenna design
    • Block diagrams — sometimes included, showing the RF chain architecture
    • Test reports — conducted and radiated emissions data, which can reveal operating frequencies and power levels
    • Label placement — where the FCC ID lives on the device

    What the FCC filing does not include: schematics (usually withheld under confidentiality requests), firmware, bill of materials, or debug interface documentation.

    What we reveal

    The FCC tells you what a device emits. We tell you what’s inside and how it works.

    • Chip-level identification — every major IC named, with datasheet links where public documentation exists
    • Board mapping — what connects to what, which test pads matter, where the debug interfaces hide
    • What the manufacturer won’t tell you — undocumented features, hidden radios, silent telemetry, repair blockers

    Key Chips

    • ESP32 — the original dual-core Xtensa. The chip that made $3 Wi-Fi possible.
    • ESP32-S3 — current workhorse for new designs.
    • ESP32-C3 — RISC-V, often under $1 in volume.

    Espressif publishes full technical reference manuals, datasheets, and hardware design guidelines — a stark contrast to most chip vendors. See our datasheet index.

    Security Research & Notes

    CVE-2025-27840: Undocumented Bluetooth HCI commands (2025)

    In March 2025, Tarlogic Security disclosed 29 undocumented vendor-specific HCI commands in the original ESP32’s Bluetooth firmware — including commands that could read/write RAM and flash. Initial coverage called it a “backdoor.”

    Espressif responded that these are standard debugging and manufacturing-test commands (common across Bluetooth implementations), not intentional backdoors. They require HCI access — meaning physical access or prior firmware compromise — and are not remotely exploitable over Bluetooth alone. Espressif committed to removing them from future firmware. CVSS 6.8 (Medium).

    This is how responsible disclosure is supposed to work: researchers found it, the vendor acknowledged it, and a fix was committed.

    Sources: SOC Prime, Espressif security advisories

    Espressif’s open documentation (positive)

    Credit where due: Espressif is one of the few chip vendors that publishes comprehensive, public, no-NDA documentation — technical reference manuals, datasheets, hardware design guides, and open-source SDKs (ESP-IDF). This is the model BareBoard wishes every vendor followed. Open docs don’t prevent vulnerabilities, but they let the community find and fix them.

    Flipper Zero

    A $169 pocket multi-tool for RFID, NFC, sub-GHz, infrared, iButton, Bluetooth, and GPIO — with open firmware and schematics. Use it on your own systems, or with written authorization.

    What it is

    A handheld, microcontroller-based multi-tool, not a phone and not a computer. It reads, stores, and replays low-power radio and contactless signals, and it can act as a USB HID device, a serial terminal, and a GPIO tool. Its strength is also its warning: the same tool that shows a weak access system can be misused on a system you do not own. Use it only on your own equipment or with written authorization.

    • Price, official store: $169, microSD card not included in the basic pack.
    • Screen: 128x64, 1.4-inch monochrome LCD, backlit.
    • Battery: LiPo 2000mAh, USB-C charging.
    • Size / weight: 100 x 40 x 25 mm, 102g.
    • Official docs: docs.flipper.net, flipperzero.one, and open firmware on GitHub (flipperdevices).

    FCC filing

    FCC ID: 2A2V6-FZ, IC 27624-FZ, applicant Flipper Devices Inc, model FZ.1. The radio test report is public record, tested under FCC Part 15 Subpart C.

    • What the filing includes: external photos, internal photos, test setup photos, RF test reports, and the user manual — public record at fccid.io.
    • What it does not include: schematics (usually withheld under confidentiality), firmware, bill of materials, or debug documentation. For those, use the official open schematics and firmware below, not the FCC filing.

    Source: FCC test report for 2A2V6-FZ, and the Flipper Zero filing summary on fccid.io.

    Lawsuits and discovery

    No court lawsuit against Flipper Devices was found in Watchmen's check on 2026-10-08, and no court case was found in the public reporting reviewed for this page. The record below is regulatory and marketplace action, not a lawsuit. If a verified court case exists, it belongs here with a citation — do not add one without it.

    • US CBP, late 2022: about 15,000 units seized, later released after review.
    • Brazil ANATEL, from March 2023: shipments seized and certification blocked, with EFF intervention.
    • Amazon, April 2023: sale banned as a card-skimming device, following the Brazil seizures.
    • Gatwick Airport, September 2023: confiscation reported in Watchmen.
    • Canada, February 8, 2024: government announcement proposing to examine a ban on devices associated with copying vehicle-entry signals, explicitly naming Flipper Zero. An announcement and a consultation are not the same as an enacted prohibition.

    Flipper Devices' response, as reported: the device cannot hijack cars built after the 1990s, because those use rolling codes, and it cannot actively block the owner's signal to catch the original — a point to check against the specific vehicle and system, not as a blanket rule for every car.

    Newer generation — Flipper One is not a successor

    Flipper One, announced in May 2026, is not a newer generation of Flipper Zero. It is a parallel product, marketed in addition to Flipper Zero, focused on networks rather than local protocols.

    Flipper Zero (this page)Flipper One (parallel, in development)
    FocusOffline protocols: NFC, RFID, sub-GHz, IR, iButton, GPIOIP networking: Ethernet, Wi-Fi, routing, VPN, Linux
    CoreSTM32WB55RG microcontroller, CC1101, ST25R3916Rockchip RK3576 ARM computer + Raspberry Pi RP2350B co-processor
    ConnectivitySub-GHz, NFC, RFID, IR, BLE 5.0, USB-CWi-Fi 6E, dual Gigabit Ethernet, M.2 for 5G modem, USB, HDMI
    SystemFlipper firmware + appsLinux / Flipper OS, in development
    StatusAvailable product, $169Not yet a finished product for sale; price target around $350, not an official final price; crowdfunding planned later in 2026

    Parts taken out / put in, in focus terms: One does not swap Zero's CC1101/NFC/IR core for a faster version of the same core — it puts in a full ARM Linux computer, Ethernet, and Wi-Fi 6E, and moves away from Zero's offline-protocol focus. A true Zero successor, if one appears, will get its own exploded view here, with parts taken out and parts put in, part by part.

    Simple hardware guide — Flipper Zero

    Connect by USB-C cable to your computer. That is the first, official path. Do not open the device, do not solder, and do not guess a debug pinout to start. If you need a debug probe later, use the Basic Bash Box below, after you have identified the device over USB.

    Flipper Zero first: connect by USB-C cable first. The official path to speak to it is its USB serial CLI and the official Flipper app / qFlipper. Use the Bash Box below to find your port, then use the USB serial path. SWD pin numbers for this board are not published in this draft until they are verified from the official schematic — do not guess them.

    Basic Bash Box — talk to this device

    You have followed the hardware guide above and the device is physically connected. Now, in order: (1) open a terminal, (2) find the port, (3) speak to the device. Do not flash, erase, or write anything until step 3 identifies the device correctly.

    Step 0 — Open a terminal

    • macOS: Cmd + Space, type Terminal, press Enter.
    • Linux: Ctrl + Alt + T.
    • Windows: Windows key, type PowerShell, press Enter. For serial, you may also use PuTTY, or WSL for the Linux commands below.

    Step 1 — Find the port (connect first, then type)

    macOS:

    $ ls /dev/tty.usb* /dev/ttyACM*
/dev/tty.usbmodem1234567

    Linux:

    $ ls /dev/ttyUSB* /dev/ttyACM*
/dev/ttyACM0

    Windows (PowerShell):

    PS> Get-PnpDevice -Class Ports | Select-Object FriendlyName, InstanceId
# Look for a COM number, for example COM4

    Your port name is the [PORT] in every command below. If nothing appears, unplug, replug, and try again — do not guess a port.

    Step 2A — Speak over UART / serial (most devices, first)

    UART is a text conversation. 115200 is the speed (baud) unless the device page says otherwise.

    macOS / Linux:

    $ screen [PORT] 115200
# Type, and watch for a prompt. To quit screen later: Ctrl-A, then K.

    Windows (PuTTY): Open PuTTY, choose Serial, enter COM4 (your COM number), set Speed to 115200, click Open.

    Windows (WSL): Use the Linux screen command above with your WSL serial port, after confirming it in Windows Device Manager.

    Step 2B — Speak over SWD / JTAG / debug (when the device page names a debug probe)

    Replace [PROBE] with your probe (for example stlink, cmsis-dap, or picoprobe) and [TARGET] with the chip named on the device page. Identification only — no writing yet.

    OpenOCD, all operating systems (same command, once OpenOCD is installed):

    $ openocd -f interface/[PROBE].cfg -f target/[TARGET].cfg -c "init; dap info; shutdown"
# Look for the chip ID / TAP ID. If it does not match the device page, STOP.

    Black Magic Probe (GDB, as used on BareBoard's Watchmen bench):

    $ arm-none-eabi-gdb
(gdb) target extended-remote [PORT]
(gdb) monitor swdp_scan
# Your target appears here. Then, and only then, attach with: monitor attach

    JTAG chain check (OpenOCD):

    $ openocd -f interface/[PROBE].cfg -f target/[TARGET].cfg -c "init; scan_chain; shutdown"
# This lists the JTAG chain. It writes nothing to flash.

    Step 3 — Verify, then stop safely

    • Does the prompt, chip ID, or version string match the device page? If not, stop — you may be talking to the wrong device or the wrong port.
    • Use only your own device, or a device you have written authorization to test. This is not legal advice — it is a workbench rule.
    • To disconnect: quit the terminal program first (screen: Ctrl-A, then K; GDB: quit), then unplug.

    Device-specific fill-in: the device page above this box must name its [PORT] pattern, baud rate, [PROBE], and [TARGET]. If a page does not name them, that interface is not yet verified for that device — do not guess it.

    Fix it — choose what you want this device to do

    Find your problem below, follow that branch only, then leave. You do not need to read the whole page.

    • Update it safely — official firmware only
    • Tell it to quit spying / transmitting — turn off what you do not want
    • Remove unwanted apps / malware — clean it, then verify
    • Check what it is doing — see what it runs and what it sends
    • Start clean and leave — reset, verify, disconnect

    Update it safely

    Beginner: Use only the official update path named on this page (official app, official site, or official firmware file). Do not use a random download, a forum file, or a third-party firmware unless this page names it and says why.

    Advanced: Use the Basic Bash Box above to identify the device first, then follow the official update command for this device. After updating, check the version string — it must match the official release for this device.

    Tell it to quit spying / transmitting

    First, what this device actually does — do not assume every device spies the same way:

    • If this page lists cloud, telemetry, microphone, camera, location, or Bluetooth/Wi-Fi transmission for this device, the steps below turn that specific thing off, in the device's own settings.
    • If this page does not list such transmission for this device, there is nothing to turn off here — and this branch will say so, rather than inventing a spy feature.

    Beginner: In the device's own menu/settings, turn off Bluetooth, Wi-Fi, cloud sync, voice, camera, and location — only the ones this device actually has. Then power it off and on, and check that the setting stayed off.

    Advanced: Use the Bash Box to list what is running and what radios are on, then disable the specific radio/service named on this page. Do not block a radio you need for the fix itself.

    Remove unwanted apps / malware

    Beginner: Delete any app, skill, or add-on you did not install, from the device's own app list. Then update from the official path above — an update often replaces tampered files with clean official ones.

    Advanced: Identify the device with the Bash Box, list installed apps/files, remove only the named unwanted item, then re-check the list. If you cannot identify what a file is, do not delete system files — ask for a verified correction on this page instead.

    If malware persists after an official update and a clean reset, that fact belongs in the device page's controversies section, with a source — not as a guess in this branch.

    Check what it is doing

    Ask the device what it runs: version string, installed apps, and — where the device page names it — radio/network status. Compare each answer to this page. A mismatch is the signal to use the update or remove branch above.

    Start clean and leave

    Beginner: Use the device's own factory reset, then set it up again from the official path, then check the version string once more.

    Advanced: After reset, use the Bash Box to confirm the clean version, then disconnect: quit the terminal program first, then unplug.

    Done. You found your device, fixed it, and left — no account was needed.

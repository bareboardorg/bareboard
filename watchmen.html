Who Watches the Watchmen?

“WHO WATCHES THE WATCHMEN?”

— Alan Moore, Watchmen (1986–1987). The phrase appears as graffiti throughout the graphic novel, adapted from Juvenal’s Latin “Quis custodiet ipsos custodes?” (Satires VI, circa 100 AD).

Every instrument on the BareBoard bench exists to answer one question: what is really inside this hardware? This page turns that question around. The logic analyzers, debug probes, and programmers we trust with our examinations — do we know what is inside them?

A tool that sits between you and a target can shape everything you observe. A closed chip, an unverifiable firmware blob, a driver you cannot inspect: each one is a place where trust replaces evidence. That is acceptable only when it is a conscious choice. Below, each tool on our bench is examined the same way we examine everything else — chip by chip, license by license. Trust, but verify — starting at home.

The examinations

For each tool: what is on the board, how open the design and firmware are, whether an independent person can verify its behavior, and anything worth watching.

Glasgow Interface Explorer

What it is: a reconfigurable USB multitool for communicating with digital hardware — UART, SPI, I²C, JTAG, and many other protocols, defined in software and synthesized onto an FPGA.

What is on the board: a Lattice iCE40HX8K FPGA (supported by a fully open-source FPGA toolchain) and a Cypress FX2 high-speed USB interface, with 16 level-shifted GPIO channels.

How open is it: the gateware is written in Amaranth (a Python-based hardware description language) and released under permissive terms (0BSD / Apache-2.0); the host software is Python. The board design is open. It is built with Project IceStorm, the community reverse-engineered open toolchain for iCE40 — no vendor license, no account, no closed synthesizer required.

Can you verify it: yes, completely. Every layer from gateware source to bitstream can be rebuilt with open tools and compared.

Anything to watch: very little. Glasgow is the reference example of a fully verifiable instrument. The main practical note is that the FPGA bitstream is generated on demand, so reproducing an exact historical bitstream requires the same toolchain versions.

Raspberry Pi Pico

What it is: a $4 microcontroller board, widely used on this bench as a USB-to-serial adapter and as a debug probe (running Picoprobe firmware) for SWD targets.

What is on the board: the RP2040 microcontroller (dual Arm Cortex-M0+, 264 KB SRAM) plus 2 MB of external flash. The RP2040 contains a mask-ROM bootloader that presents the board as a USB drive — firmware is installed by dragging a file onto it.

How open is it: Raspberry Pi publishes the board design files, the RP2040 datasheet is unusually thorough for the industry, and the Picoprobe firmware is open source. The mask-ROM bootloader itself is fixed in silicon and cannot be independently rebuilt, but its behavior (USB mass storage + UF2 flashing) is documented and observable.

Can you verify it: largely yes. The firmware you run is firmware you can build from source; the ROM bootloader’s behavior is simple and well documented.

Anything to watch: the ROM is the one closed corner — small, documented, and fixed, but closed. For a $4 probe, this is an acceptable and conscious trade.

Bus Pirate v3

What it is: a USB multitool for UART, SPI, I²C, 1-Wire, and more, controlled from a serial terminal. A long-standing community instrument.

What is on the board: a Microchip PIC24FJ64GA002 microcontroller, an FTDI FT232RL USB-to-serial chip, and a 4066 analog switch array, with an ICSP header for programming the PIC directly.

How open is it: the hardware design is released under CC-0 and the firmware under CC-0, with a GPL v3 bootloader. Schematics, part lists, and firmware source are published by Dangerous Prototypes.

Can you verify it: yes. The firmware can be rebuilt and re-flashed over USB via the bootloader, or through the ICSP header with an external programmer.

Anything to watch: the FTDI FT232RL is a closed chip (as with all FTDI parts) — it handles USB only, not protocol logic, so its closed nature has limited bearing on measurement integrity. Note that FTDI’s drivers have a history of aggressive counterfeit-chip handling; genuine boards avoid the issue.

Tigard

What it is: an open-source FTDI FT2232H-based multi-protocol tool (UART, JTAG, SPI, I²C, SWD) with on-board level shifting from 1.8 V to 5.5 V, designed for attaching to low-speed interfaces on examined hardware.

What is on the board: an FTDI FT2232HQ dual high-speed USB interface chip, bi-directional level shifters, and dedicated headers for UART, SWD, JTAG, SPI, and I²C, plus a logic-analyzer tap header.

How open is it: the board design is released under Creative Commons Attribution-ShareAlike 4.0, with design files on GitHub. It works with standard open tools (OpenOCD, Flashrom, PyFtdi).

Can you verify it: the board design, yes. The FTDI chip’s internal firmware is closed, but the chip is used as a standard USB interface whose behavior is defined by FTDI’s public drivers and the open host-side tools.

Anything to watch: same FTDI note as the Bus Pirate: the closed USB interface chip is a transport, not the measurement logic. Verify the level-shifter voltage selection before connecting to a target — wrong voltage is a hardware risk, not a trust issue.

Shikra

What it is: an FTDI-based USB adapter for JTAG, SPI, I²C, UART, and GPIO, from Xipiter.

What is on the board: an FTDI interface chip (USB to the low-level protocols listed above).

How open is it: less documented than the others here. Public design files and firmware sources are limited, which is itself the finding.

Can you verify it: partially. It works with standard FTDI-compatible host tools, so its observable behavior can be checked, but the board-level design is not as openly published as the tools above.

Anything to watch: this is the weakest link on the bench from a verifiability standpoint. It remains useful, but it is used with that limitation in mind — and it is a candidate for replacement by a fully open equivalent.

Saleae-compatible logic analyzers (FX2-based)

What it is: inexpensive 8-channel, 24 MHz USB logic analyzers, widely sold as low-cost alternatives to the original Saleae Logic.

What is on the board: a Cypress CY7C68013A (FX2LP) USB controller, an NXP LVC245A transceiver, a 24C02N I²C EEPROM, and a 24 MHz crystal. (Documented by the sigrok project’s hardware notes.)

How open is it: the hardware is an unlicensed copy of the original design — not open, and not authorized. The redeeming factor is the firmware: sigrok’s fx2lafw is fully open-source firmware that these boards can run, replacing the factory-installed firmware.

Can you verify it: yes, when running fx2lafw under sigrok/PulseView. The firmware is built from source and loaded onto the FX2LP at each session.

Anything to watch: two things. First, the hardware’s provenance is a copy — buy it for the price, not the brand story. Second, always run the open firmware; the firmware a clone ships with is of unknown origin. With fx2lafw loaded, the instrument is verifiable.

CH341A programmers

What it is: ~$3 USB programmers for SPI flash and I²C EEPROM (25-series / 24-series), used with a SOIC-8 test clip to read chips without desoldering.

What is on the board: the WCH (Nanjing Qinheng) CH341A USB interface chip, a voltage regulator, and a ZIF socket or pin header. The CH341A itself is closed silicon.

How open is it: the chip is closed, and the bundled vendor software is of uncertain provenance. The community answer is open host software: AsProgrammer (MIT-licensed) and flashrom both support the CH341A.

Can you verify it: behaviorally, yes — read-back verification (read the chip, compare against what was written) is standard practice and catches misbehavior. Use the open host tools, not the bundled software.

Anything to watch: voltage. Some inexpensive boards have jumpers or design quirks around 3.3 V vs 5 V selection — always verify the output voltage with a multimeter before connecting to a 3.3 V target. A wrong voltage damages the target; this is the most common real-world failure with these boards.

The pattern is consistent: the most trustworthy tools are the ones whose designs and firmware can be rebuilt from source. Where a closed component exists, it should be isolated to transport (USB) rather than measurement — and its limitations should be stated plainly, as above.

You do.

Every claim on this site is designed to be checked. We publish our methodology, our tools, our measurements, and our sources. We photograph the boards. We link the datasheets. We show our work — not because we’re confident we’re always right, but because we’re confident the process is honest.

We don’t ask for your trust. We ask for your scrutiny.

How we stay honest

  • Show the board. Every teardown includes photographs of the actual hardware. If we say a chip is there, you can see it.
  • Name the chip. Part numbers, manufacturers, and markings — not “a mysterious black square.”
  • Link the datasheet. Every identified component links to its public documentation. See our datasheet index.
  • Label confidence. Confirmed, likely, unconfirmed — we tell you exactly how sure we are and why.
  • Cite sources. FCC filings, boot logs, manufacturer docs, community references. Nothing appears from nowhere.
  • No sponsored findings. No advertiser, no vendor, no affiliate deal influences what gets published or what it says.
  • Responsible disclosure first. Manufacturers hear about a finding before the public does.
  • Nothing weaponizable. We never publish weaponizable material or reconstructed commercial firmware in ways that could put people at risk.
  • Verified findings only. Every claim is backed by our own hardware work, not rumors or leaks.

BareBoard is not a collective for unauthorized access, not a leak site, and not a shortcut around anyone’s security. It is a bench, a notebook, and a publishing desk — in that order.

The bench

Claims are only as good as the instruments behind them. These are the most widely used tools in hardware research — the ones you’ll find on benches everywhere, including ours:

  • Saleae Logic Pro 8 / Logic 8 — the logic analyzer. Captures UART, SPI, I2C, and unknown digital protocols straight off the board. It captures digital signal transitions reliably.
  • Rigol DS1054Z — a widely adopted oscilloscope. Four channels, 50 MHz (software-upgradable to 100), under $400. It is widely used in electronics laboratories.
  • Fluke 87V / 117 — the multimeter. When a reading must be trusted, it is the reference instrument.
  • Hakko FX-888D — the soldering iron. Blue and yellow, indestructible, and commonly found in electronics laboratories.
  • Pinecil — the open-source iron. USB-C powered, $25, community firmware. Proof that open hardware can win.
  • Quick 861DW — the hot-air station for lifting shields and QFN packages without destroying the board.
  • Bus Pirate — the classic multitool. Talks UART, SPI, I2C, 1-Wire, and more from a single board. an open-source contribution from Dangerous Prototypes.
  • Glasgow — the open-source USB interface explorer. The new standard for communicating with uncommon hardware.
  • Segger J-Link — the JTAG/SWD debugger. When the debug headers are populated and the silicon can be analyzed.
  • ST-Link V2 — the affordable ST debugger. Compatible units are widely available.
  • FTDI FT232 / CH340 breakouts — USB-to-serial adapters. A standard choice for UART interface work.

No tool makes a finding true. But the right tool makes it checkable — and everything above is something you can buy, borrow, or build yourself.

When we’re wrong

We will be wrong sometimes. Hardware is hard, markings lie, and manufacturers obfuscate. Here’s what happens then:

  • Tell us. Found an error? Contact us. The more specific, the better — photos and measurements help.
  • We verify. Every correction gets checked against the hardware, not just taken on faith.
  • We fix it publicly. Corrections are made in the open, on the page, where everyone can see what changed and why.
  • No stealth edits. If a finding changes materially, we say so. The record matters.

Accuracy isn’t a claim we make about ourselves. It’s a process you can watch.

No trust required

The tech press runs on access and relationships. We run on evidence. You don’t need to believe us — you need a multimeter and the datasheet. That’s the whole point.

Quis custodiet ipsos custodes? You do. That’s why everything is published.
